## Project spec: `schema-lineage`

Here's the architecture I designed — 5 files, zero circular dependencies, all oriented toward a future graph visualization layer.

---

### Dependency order (bottom → top)

```
models.py
    ↑
parser.py          lineage_resolver.py
    ↑                      ↑
              catalog.py
                   ↑
              __init__.py
```

---

### File summary

| File | Role |
|------|------|
| `models.py` | Frozen/plain dataclasses — `ColumnDef`, `ForeignKeyDef`, `TableDef`, `ViewDef`, **`ColumnRef`** (graph node), `LineageEdge` (directed edge), `SchemaGraph` (container). No sqlglot dependency. |
| `parser.py` | `SchemaParser` — reads the DDL file, dispatches each sqlglot AST statement to `_parse_create_table` / `_parse_create_view`, normalizes names, extracts PKs and FKs. Returns a `SchemaGraph` *without* lineage edges. |
| `lineage_resolver.py` | `LineageResolver` — builds a `{table: {col: type}}` schema context for sqlglot, toposorts views, then calls `sqlglot.lineage.lineage()` per output column to walk source nodes and emit `LineageEdge` objects. |
| `catalog.py` | `SchemaCatalog` — wraps the complete `SchemaGraph` with O(1) upstream/downstream indices, `transitive_upstream/downstream` BFS walkers, a `lineage_adjacency()` dict, and a `to_dict()` JSON export ready for a viz front-end. |
| `__init__.py` | `parse_schema(path, dialect='ansi') → SchemaCatalog` — chains all three layers in one call; re-exports key types. |

---

### Design decisions for visualization readiness
- **`ColumnRef`** is the graph node type — hashable, case-insensitive, carries `schema.table.column` identity.
- **`LineageEdge`** is a typed directed edge, not a raw tuple — easy to serialize or convert to NetworkX/D3 edges.
- **`SchemaCatalog.lineage_adjacency()`** returns a plain `dict[ColumnRef, list[ColumnRef]]` — drop it straight into any graph library.
- **`to_dict()`** gives a JSON-serializable snapshot for front-end consumption.
- Multi-source columns (e.g. `COALESCE(a.x, b.y)`) emit one edge per source — the graph stays accurate for impact analysis.
