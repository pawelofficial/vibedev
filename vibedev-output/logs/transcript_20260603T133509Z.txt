Here's the spec for **flask-calculator** — a 5-file project laid out in strict dependency order:

| Layer | File | Role |
|---|---|---|
| 0 | `config.py` | `Config` class — all tunables, no Flask/calculator imports |
| 0 | `calculator.py` | `Calculator` + `CalculatorError` — pure-Python AST-based engine, zero Flask |
| 1 | `routes.py` | `create_blueprint(calc)` — Blueprint factory, wires HTTP ↔ engine |
| 2 | `app.py` | `create_app()` + `main()` — factory entry point, ties everything together |
| UI | `templates/index.html` | Jinja2 + inline CSS/JS — glassmorphism card, fetch-based, no CDN |

**Key design decisions:**

- **No `eval()`** — `calculator.py` uses `ast.parse` + a whitelisting `NodeVisitor` so only literals and `+`, `-`, `*`, `/` nodes are allowed; anything else raises `CalculatorError`.
- **Dependency injection** — `create_blueprint` accepts a `Calculator` instance, making the routes trivially testable without touching Flask's app context.
- **Self-contained UI** — the template has no external CDN links; CSS glassmorphism (backdrop-filter, blur, semi-transparent card) and JS (fetch POST to `/calculate`, shake animation on error) live inline.
- **Acyclic graph** — `config` and `calculator` are leaves; `routes` depends on both; `app` depends on all three. No cycles.
